# 设备通信底层（第一阶段）

当前实现覆盖设计文档中已明确的 TCP 与二进制帧约束，并通过模拟采集服务验证连接、属性查询、开始和停止命令链路。

已于 2026-08-29 与本机 `127.0.0.1:7110` 的真实采集软件完成属性查询：1000 Hz、每包 100 点、33 通道。真实导联名称使用空格/制表符补齐，适配器已兼容该格式。

同日设备尚未连接时的诊断曾确认开始命令可使属性 0 从 `0` 变为 `1`，但普通推流和显式属性 05 请求均没有 EEG；这说明数据流服务器在线并不等于脑电硬件已经出流。

设备与数据流服务器正确开启后，10 秒真机采集成功收到 95 帧：每帧 3300 个值（33 通道 × 100 点）、13200 字节 payload、0 个非法帧。真机还确认停止命令发送后需要短暂保持 TCP 连接；采集器现等待 0.5 秒再关闭。

## 阶段 2 验收结果

- 设备客户端具有明确的连接、查询、启动、采集、停止和故障状态；
- 属性响应与 EEG 交错到达时使用有序待处理队列，不再按属性号覆盖；
- EEG 数据块生成网关序号和连续样本索引；
- 有界队列溢出时记录丢弃数量及序号范围；
- 记录非法帧、非 EEG 帧、最大队列深度和疑似传输间隔；
- 支持带退避的有限次数重连；断线后进入 `faulted`；
- 停止命令等待 0.5 秒后查询属性 0，区分 `device_status` 与较弱的 `sent` 确认；
- 95 帧真机文件回放结果：95 帧有效、0 非法、0 丢弃、0 疑似间隔；
- 30 秒真机采集：296 帧有效、0 非法、0 队列丢弃、7 次疑似到达间隔；
- 5 秒停止确认验收：46 帧有效，`stop_confirmation: device_status`；
- 自动测试共 13 项。

设备帧没有原生序号，因此“疑似传输间隔”只是依据采样率和到达时间产生的告警，不能证明设备端实际丢包。

## 阶段 3：本地会话存储

正式的本地录制入口：

```powershell
python -m device_gateway.record_session --seconds 10
```

每个会话写入 `sessions/<sessionId>/`：

- `session.json`：版本、设备属性、状态、记录数和完成原因；
- `eeg.bin`：版本化二进制记录，包含网关序号、首样本索引、单调时钟和原始设备帧；
- `events.jsonl`：生命周期和异常事件；
- `markers.jsonl`：刺激标记；
- `decisions.jsonl`：分类决策。

元数据使用临时文件和原子替换。应用重启时可调用 `recover_incomplete_sessions()`，把遗留的 `in_progress` 会话标记为 `incomplete`，不会删除原始 EEG。

## 阶段 4：本地 WebSocket 网关

`websocket_server.py` 提供只绑定回环地址的单客户端网关：

- 首条消息必须以一次性 token 和 `protocolVersion: 1` 完成 `hello`；
- JSON 控制命令包括属性、状态、开始、停止、断开、marker 和 shutdown；
- EEG 使用带 `BGEE` 魔数、会话 UUID、序号、样本索引和时钟的二进制消息；
- 二进制发送队列有固定上限，慢客户端只会丢弃旧数据并记录计数，不阻塞设备接收；
- 客户端异常断开时触发安全停止；
- 当前使用标准库实现最小 WebSocket 协议，无额外在线依赖。

真机 WebSocket 链路检查：

```powershell
python -m device_gateway.gateway_smoke --seconds 3
```

阶段 4 真机验收：通过 `ws://127.0.0.1:<randomPort>` 完成 token 握手，3 秒收到 25 个连续二进制块（序号 0–24），发送队列丢弃 0，停止确认为 `device_status`。

## 阶段 5：Electron 桌面外壳

桌面代码位于 `desktop/`，renderer 位于 `renderer/`。当前包括：

- Electron 单实例窗口和第二实例聚焦；
- `sandbox: true`、`contextIsolation: true`、`nodeIntegration: false`；
- 禁止任意新窗口和外部导航；
- 自动创建日志、同步队列和用户会话目录；

- token 仅保存在当前进程内，不写入日志或配置；
- preload 只暴露网关状态、连接信息、重启和打开会话目录；
- 最小 React/Vite 状态页面，不包含设备协议或 Node 权限。

## 阶段 7：Signal Worker

- Dedicated Web Worker 独立于 React 主线程处理 EEG；
- 20 秒多通道环形缓冲和连续样本索引；
- 50 Hz 陷波、6–45/14–45/22–45 Hz 三子带预处理；
- 8/10/12/15 Hz、三次谐波频率评分；
- 1 秒窗口、0.5 秒步长、置信度和领先幅度门控；
- 三个连续窗口投票，低置信度、投票不稳定或传输间隔时拒识；
- 输出统一 `BciDecision`，包含会话、试次、样本范围和算法版本；
- Worker 配置时运行确定性 10 Hz 合成信号自检。

当前分类器明确标记为 `fbcca-prototype 0.1.0`。它已验证数据链路和频率响应，但尚未使用带刺激 marker 的标注真机数据评估准确率，不应作为最终实验算法结论。

阶段 7 真机链路验收：3500 点/通道、6 个滑动窗口、0 无效块。无视觉刺激时曾出现 0.360 的偶然候选，因此原型阈值已保守提高到 0.45；调整后复测置信度 0.324，正确拒识为 `low_confidence`。正式阈值必须在阶段 8 使用带刺激 marker 的数据校准。

## 阶段 8：逐帧刺激与试次状态机

- 新增 Canvas 正面俯视牌桌原型：牌面静止，牌后独立矩形光带按连续正弦波逐帧改变亮度；
- 启动时通过 `requestAnimationFrame` 中位帧间隔检测实际刷新率，并使用检测结果生成刺激序列，不再假定显示器为 60 Hz；
- 实现 `dealing → fixation → preview → stimulus → feedback → rest` 单一试次流程；刺激最长 4000 ms，Worker 稳定决策后可动态提前结束；
- 只有 Canvas 首个实际刺激帧才启动 Worker 试次并发送 `stimulus_start`，结束时记录实际持续时间、渲染帧数、刷新率和疑似掉帧；
- WebSocket 新增 `bci_decision` 控制消息；真实网关把原始 EEG、marker 和决策写入同一不可变会话目录；
- 会话停止后原子完成 `session.json`，并保留 `eeg.bin`、`markers.jsonl`、`decisions.jsonl` 和 `events.jsonl`。

阶段 8 真机验收使用当前采集软件完成一次自动试次：1000 Hz、33 通道、每包 100 点；记录 87 个 EEG 帧、每通道 8700 点、0 序号不连续、0 网关间隔告警。显示器预检识别为 165 Hz，刺激帧实测中位刷新率约 161.29 Hz，210 帧中 0 个疑似掉帧；开始/结束 marker 和两次 Worker 决策成功写入同一会话，页面无错误。

本阶段的提前选择仍由 `fbcca-prototype 0.1.0` 产生。它只验收了刺激、时间戳、EEG 和决策的端到端链路；本次无受控注视标签，结果不得解释为分类准确。下一阶段需要生成平衡目标提示、采集带标签校准数据，并训练/验证个体 eTRCA 模板与拒识阈值。

## 阶段 9：校准与个体 eTRCA 原型

- 新增交替目标提示的校准试次；校准刺激固定播放 4000 ms，不因中途候选结果提前结束；
- Worker 在每个校准试次结束时保存所选枕区通道窗口，并按目标统计有效样本数；
- 提供每目标 2 次的“快速校准”用于工程链路检查；正式校准仍要求每目标至少 12 个有效试次；
- 新增基础 eTRCA 原型：按目标计算试次间可重复协方差、正则化空间滤波器和个体平均模板；原始 EEG 仍以 1000 Hz 落盘，模型模板降采样到 250 Hz；
- eTRCA 模型训练完成后，Worker 在线决策自动从 FBCCA 基线切换到 `etraca-prototype 0.1.0`；FBCCA 保留为未校准后备；
- 模型以 `calibration-model.json` 写入当前会话，保存算法版本、通道、采样率、每目标试次数、空间滤波器和模板；
- marker 现在包含网关估算的 `markerSampleIndex`。Worker 在收到样本索引前暂存 EEG 数据包，收到后按全局样本索引裁切，避免直接把数据包边界当作刺激起点；
- WebSocket 新增 `calibration_model` 命令，并继续将模型、marker、决策与原始 EEG 绑定到同一会话。

阶段 9 真机工程验收：完成左右目标各 2 次、共 4 个固定 4 秒校准试次，随后训练模型并运行一次在线识别；会话共记录 415 个 EEG 帧、每通道 41500 点、10 条 marker，5 个刺激开始 marker 均包含递增的样本索引。模型包含 2/2 个目标试次、2 个空间滤波器和 2 个模板，在线决策的分类器名称成功切换为 `etraca-prototype`，页面无错误。

自动冒烟测试没有要求操作者按目标进行受控注视，因此只能证明校准、训练、持久化和在线推理链路连通，不能评估 eTRCA 准确率或相位编码收益。当前也是基础 eTRCA 原型，尚未扩展为三个子带分别训练和融合的滤波器组 eTRCA。下一步必须由真实用户按提示完成平衡校准与独立验证，再决定滤波器组、阈值和动态停止参数。

## 模块边界

- `transport.py`：纯字节流传输。当前为 TCP，以后可替换为串口、SDK 或其他 IPC。
- `protocol.py`：`ProtocolAdapter` 接口及中立帧模型。
- `legacy_adapter.py`：当前本地脑机采集软件的协议适配器。
- `frame_parser.py`：处理半包、粘包、噪声、错误帧尾及长度上限。
- `eeg_decoder.py`：显式小端 float32、样本优先/通道交错解码。
- `device_client.py`：连接、属性查询与采集控制流程，不包含厂商帧常量。

更换采集软件时，新建一个 `ProtocolAdapter`；如果传输方式也变化，再实现新的 `Transport`。`DeviceClient` 及其上层接口原则上无需修改。

## 限时采集真实 EEG 样例

```powershell

```

`captures/` 默认被 Git 忽略，因为真实 EEG 属于实验数据，不应提交到源码仓库。

```powershell
python -m device_gateway.capture --seconds 3 --request-eeg-property
```

该参数是当前采集软件的可选诊断行为，没有放入通用 `Transport` 接口。

## 阶段 16：固定信号分析导联

- 信号预处理、FBCCA、eTRCA 校准和在线识别严格只取 `O1、O2、P3、P4` 四个导联。
- 导联名称会自动去除采集软件可能附带的空格；缺少任一指定导联时，Worker 直接报错并阻止分析启动，不回退到其他通道。
- 原始 EEG 仍保存设备提供的全部通道，便于后续复核和更换算法。
- 真机训练发现两目标 eTRCA 模型约 118 KB，超过原 64 KB WebSocket 控制帧上限并触发断连。认证后控制消息上限已调整为 4 MB，未认证 hello 仍限制为 16 KB。
- 新增 128 KB `calibration_model` 回归测试，验证模型保存成功后同一 WebSocket 仍可继续响应命令；UI 保存完成前锁定停止采集。
- 浏览器大消息可能使用 WebSocket continuation 帧；网关现支持在总大小限制内组装分片文本/二进制消息，并新增 128 KB 两帧分片模型保存测试。协议错误会输出到开发终端，不再静默断开。

## 阶段 17：预处理与简单刺激参数明确化

- 新增 `renderer/src/bci/signal/preprocess.ts`，将在线分析预处理固定为“逐导联去均值”，移除重参考步骤。校准和在线推理共用同一函数，避免训练/推理流程不一致。
- `signal.worker.ts` 直接使用四个独立导联，分析导联仍严格为 `O1、O2、P3、P4`。
- `SIMPLE_TARGETS` 当前被试复测频率版本为 `simple-frequency-v6`：左 `12 Hz / 0 rad`、右 `15 Hz / π/2`，几何使用 `simple-geometry-v2` 的 `(0.24, 0.64)` 与 `(0.76, 0.64)`；v4/v5 及更早数据不得混入同一频率模型，困难 1/2 的演示频率保持原配置。
- 新增 `python -m device_gateway.inspect_eeg`，读取会话 `eeg.bin` 或限时采集 `device-frames.bin`，按同样预处理输出四导联时域统计、通道相关性和 1–45 Hz 频谱峰值；加 `--plot` 生成 PNG。

## 阶段 18：离线 marker 回放校验

- 新增 `python -m device_gateway.validate_session --session <session-dir>`，在不连接采集设备的情况下检查 `stimulus_start`/`stimulus_end` 配对、样本索引顺序、目标位置、频率唯一性及教学布局版本。
- 历史教学及操作训练 marker 记录 `teaching-geometry-v3`、隐藏中央参考牌和横向单排。放大的原理演示使用 `teaching-geometry-v5` / `teaching-fill`，两/三/四目标均为单排；同时保存实际画布、牌面、外围和标签几何。历史 `teaching-geometry-v4` 的四目标2×2记录仍支持回放。回放校验检查版本与目标数、模式匹配；校验失败时直接返回错误。
- 该校验只验证会话可复现性，不代表 EEG 分类准确率或真人实验通过。

## 当前验证边界

以下值来自架构文档，尚须用 `communication2.2.py` 和真实采集帧建立 golden vectors：

- EEG 是否确为 little-endian float32；
- EEG 数值单位已由用户确认：网络输出为 μV，不再进行幅值换算；
- 真实最大 `data_length`；
- 开始/停止采集的设备确认机制；
- 采集中能否并行查询属性。

`sample_unit` 统一为 `μV`，新建采集记录及会话元数据记录该单位，原始数值保持不变。历史记录不追溯改写。其他未确认事实的验证边界仍保留，负载上限保持可配置，开始/停止状态仅代表命令已发送。
