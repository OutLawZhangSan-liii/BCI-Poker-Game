# main 三关挑战与排行榜

## 目标与已实现行为

main 在原有 Electron/React 结构中增加实名三关挑战、四类本机排行榜和中断恢复。简单→进阶→困难各10轮，每次完整挑战独立排名。保留自由游戏、教学、设备入口。

用户在实现期间追加要求“取消目前游戏的拒识重试策略”。据此自由游戏和挑战均改为：每轮一次有效识别，正确／错误／拒识都推进；拒识得0分并中断连胜，异常取消不计成绩。规则版本 `three-stage-v1-no-retry`。首次与最终正确率当前相等，界面统一显示“正确率”，详细说明保留两个口径。

## 定位与数据流

- [共享规则与类型](../../desktop/main/challengeModel.ts)：记录结构、验证、指标、排名、恢复与不可改写的历史校验。为避免复制规则，由渲染端和主进程共同使用；模块没有 Electron、文件系统和设备依赖。
- [本地存储](../../desktop/main/challengeStore.ts)：UUID 限定文件名、写入队列、版本检查、幂等重试、临时文件写入并同步后原子替换。JSON 文件是原始成绩依据，排名按需计算。
- [渲染端会话](../../renderer/src/game/challengeSession.ts)：在失败时保留待保存快照、阻止后续推进、重试后恢复；[主入口](../../renderer/src/main.tsx)复用既有牌桌与真实 EEG 生命周期，在刺激前保存手牌和 pending 尝试，刺激结束后保存终态。
- [界面](../../renderer/src/components/ChallengeHub.tsx)：牌桌控制区“开始本局”左侧的挑战入口，原生小弹窗先输入身份、再看简短规则；排行榜和继续挑战入口在身份弹窗底部，使用米白配色，从辅助页面返回保留身份输入。结算由现有 HUD 承载。姓名进顶部 HUD，学号只在成绩界面显示尾四位。

preload 公开 `createChallenge`、`getChallenge`、`listChallenges`、`saveChallenge`；主进程仅接受当前主窗口主框架请求，不能由调用方指定文件路径。正式目录为用户文档 `BrainGame/Challenges/`，与 EEG Sessions 分开并通过 sessionId/trialId 关联。旧 EEG 会话不迁移成实名成绩。

挑战每轮终态最多一个有效尝试，异常／进程退出留下的 pending 尝试恢复时标 invalid，保留原因。关间30秒休息截止时间持久化；继续下一关前再次检查设备和配置。完成30轮且保存确认后才上榜，禁止修改已完成成绩。保存报错后须点击重试，当前窗口保留未保存快照。

## 排名与时间

- 综合：正确率降序→所有轮次平均耗时升序→单关最长连胜降序。
- 准确：首次正确率→最终正确率→拒识次数。无重试时前两项相同。
- 速度：正确率≥70%，正确轮平均耗时升序→正确率降序。
- 连胜：最长连胜降序→正确率降序→所有轮平均耗时升序。

按完整数值比较，同排序项并列，完成时间仅稳定排列。连胜在模式间归零；得分保持既有正确100分和最多50分速度奖励。排名按规则、识别参数／采样率、刺激配置分组，后续参数修改需更新版本和指纹。

尝试记录 `logicalStartMs`、`firstFrameMs`、`endedMs`、`elapsedMs`，以应用首次绘制帧为计时起点，包含分析宽限且不裁剪到刺激截止；不包括发牌、观察、倒计时、反馈和休息。它不是硬件同步或光电延迟测量。

## 验证与限制

- `npm run test:challenge`：身份前导零、30轮拒识推进、耗时／连胜、精度和并列、70%门槛、文件故障、幂等、历史保护、恢复及模拟完整流程。
- `npm run test:challenge-ui`：先构建，再通过隔离隐藏 Electron 窗口自动操作真实 UI／preload／存储。模拟数据仅写 `.smoke-user-data/challenge-*/`，流程报告与截图同目录。额外传参仅由未打包且指定独立 userData 的测试主进程开启；模拟输入不触发真实采集或闪烁，配置也显式标记 isolated-simulation。
- 现有刺激／识别／游戏与 Python 网关回归通过；最终命令及验收目录在交付时更新。
- 真实 EEG 可玩性、实际闪烁时序和长期使用性能仍需设备现场验证；本轮不生成安装包，不进行云端排名。
